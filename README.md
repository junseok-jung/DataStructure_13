# 병합 정렬과 퀵 정렬의 성능 비교 분석

## 1. 실험 개요
무작위로 생성된 정수 데이터($n = 1,000 \sim 20,000$)에 대하여 **병합 정렬(Merge Sort)**과 세 가지 피벗 선택 방식(**First Element, Random, Median-of-Three**)을 적용한 **퀵 정렬(Quick Sort)**을 수행하고, 비교 횟수, 실행시간, 메모리 사용량을 비교·분석하였다.

## 2. 데이터 크기 증가에 따른 비교 횟수 변화
* 데이터 크기 $n$이 2배로 증가할 때, 두 알고리즘 모두 비교 횟수가 약 $2.1 \sim 2.2$배씩 증가하여 이론적인 시간 복잡도인 $O(n \log_2 n)$에 비례하는 추세를 보였다.
* **병합 정렬 vs 퀵 정렬 비교 횟수**: 모든 데이터 크기에서 **병합 정렬의 비교 횟수가 퀵 정렬보다 적게 측정**되었다.
  * **원인**: 병합 정렬은 데이터를 항상 정확히 절반($1:1$)으로 분할하므로 재귀 트리의 높이가 정확히 $\lceil \log_2 n \rceil$이 되며, 각 단계에서 최대 $n-1$번만 비교한다(약 $n \log_2 n - n + 1$회). 반면 퀵 정렬은 피벗 값에 따라 분할 비율이 완전히 균등하지 않아 평균적으로 약 $1.39 n \log_2 n$회의 비교가 발생하기 때문이다.

## 3. 두 정렬 알고리즘의 실행시간 차이
* 비교 횟수는 병합 정렬이 더 적었음에도 불구하고, 실제 **실행시간은 퀵 정렬(특히 Median-of-Three 및 First 방식)이 병합 정렬보다 더 빠르거나 유사**하게 측정되었다.
* **원인**:
  1. **데이터 이동 비용**: 병합 정렬은 매 병합 단계마다 데이터를 임시 배열(`temp`)에 복사했다가 다시 원본 배열(`arr`)로 복사하는 추가적인 데이터 이동 작업이 반복된다.
  2. **캐시 지역성(Cache Locality)**: 퀵 정렬은 추가 배열 없이 원본 배열 내에서 인접한 원소들을 연속적으로 탐색하며 교환(In-place)하므로 CPU 캐시 적중률이 높아 실제 실행 속도가 빠르다.

## 4. 두 정렬 알고리즘의 메모리 사용량 차이
* **병합 정렬**: 데이터 크기 $n$에 비례하여 메모리 사용량이 선형적으로 크게 증가하였다($n=20,000$일 때 약 80,768 Bytes). 이는 병합 과정에서 원본 배열과 동일한 크기의 임시 배열(`n * 4 Bytes`)을 동적 할당하기 때문이다.
* **퀵 정렬**: 데이터 크기가 20배 증가($1,000 \rightarrow 20,000$)하더라도 메모리 사용량은 약 $800 \sim 1,800$ Bytes 수준으로 매우 적고 완만하게 증가하였다. 임시 배열을 사용하지 않고 재귀 호출 스택만 사용하므로 $\log_2 n$에 비례하는 메모리만 소모하기 때문이다.

## 5. 퀵 정렬의 피벗 선택 방법에 따른 성능 차이
* **Median-of-Three (세 원소의 중앙값)**: 세 가지 방식 중 **비교 횟수, 실행시간, 메모리 사용량 모두 가장 우수**했다. 맨 앞, 중간, 맨 뒤 원소 중 중간값을 피벗으로 선택함으로써 극단적인 값(최솟값/최댓값)이 피벗이 되는 것을 방지하고 분할 균형을 맞춰 재귀 깊이(메모리)와 총 비교 횟수를 줄였다.
* **First Element (첫 번째 원소)**: 입력 데이터가 무작위(Random)로 생성되었기 때문에 첫 번째 원소를 선택해도 확률적으로 무작위 선택과 유사한 분할 성능을 보였다. `rand()` 함수 호출 오버헤드가 없어 실행시간은 Random 방식보다 소폭 빨랐다. (단, 정렬된 데이터가 입력될 경우 $O(n^2)$으로 급격히 저하되는 한계가 있다.)
* **Random Pivot (무작위 원소)**: 비교 횟수와 재귀 깊이는 First 방식과 비슷했으나, 매 분할마다 난수를 생성하는 `rand()` 함수 호출 비용이 추가되어 실행시간이 세 가지 방식 중 가장 길게 측정되었다.

## 6. 병합 정렬과 퀵 정렬의 시간 복잡도 및 공간 복잡도 정리

| 구분 | 병합 정렬 (Merge Sort) | 퀵 정렬 (Quick Sort) |
| :--- | :--- | :--- |
| 평균 시간 복잡도 | $O(n \log n)$ | $O(n \log n)$ |
| 최악 시간 복잡도 | $O(n \log n)$ | $O(n^2)$ |
| 공간 복잡도 | $O(n)$ (임시 배열 + 재귀 스택) | $O(\log n)$ (평균 재귀 스택, 최악 $O(n)$) |

## 7. 메모리 사용량의 측정 방법과 계산 기준
원본 데이터 배열(`n * sizeof(int)`)은 모든 알고리즘의 공통 비용이므로 제외하고, 정렬 수행 중 동시에 유지되는 **최대 추가 메모리(Peak Additional Memory)**를 아래 기준으로 계산하였다.
1. **최대 재귀 깊이(`max_depth`) 측정**: 재귀 함수 진입 시마다 `depth`를 1씩 증가시켜 정렬 과정 중 도달한 최대 재귀 호출 깊이를 측정하였다.
2. **스택 프레임 크기(`FRAME_SIZE`) 산정**: 64비트 시스템 기준 함수 호출 1회당 스택에 쌓이는 매개변수(포인터 8B, 정수 4B), 지역변수, 그리고 함수 반환 주소 및 이전 프레임 포인터(16B)의 합계인 **48 Bytes**를 1회 재귀 호출 비용으로 적용하였다.
3. **알고리즘별 계산 공식**:
   * **병합 정렬**: `(n * sizeof(int)) + (max_depth * 48 Bytes)`
   * **퀵 정렬**: `max_depth * 48 Bytes`
